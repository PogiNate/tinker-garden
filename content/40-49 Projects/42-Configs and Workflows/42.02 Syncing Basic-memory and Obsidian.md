# Introduction

[[31.01 Obsidian|Obsidian]] is obviously my tool of choice for remembering things. I'm using it right now! And I want to make my Obsidian vaults available to AI tools so that they can reference and enhance my external brain. 

I have a dedicated small server called `file-relay`. 

My preferred[^1] method of sharing Obsidian with AI is [[04.01 Basic-Memory|Basic Memory]]. So. The requirements are these:

1. Ensure that my Obsidian vaults stay up to date regardless of where I'm working on them. 
2. Ensure that Basic Memory can read/write to the vaults and the changes are synchronized. 

# Tools Used

| Need                   | Tool              | Note                                                                                       |
| ---------------------- | ----------------- | ------------------------------------------------------------------------------------------ |
| Sync with Obsidian     | `ob sync`         | This is a headless service provided by Obsidian to interact with their cloud sync servers. |
| Sync with Basic Memory | `bm cloud bisync` | the basic memory tool actually provides a lot of options, which I will discuss below.      |
| Auto-run sync tools    | `systemctl`       | The best tool!                                                                             |

## Obsidian Headless Sync

This provides some very helpful options to ensure that Obsidian vaults stay in sync. the main thing is that you can start the process and tell it to run continuously:
```bash
ob sync --continuous
```

run this in any obsidian vault directory and you're good to go. 

## Basic Memory Bisync

Basic Memory also has it's own simple sync service, once you have cloud sync set up you can run each sync with 

```bash
bm cloud bisync --name [projectname]
```

so that works well. But it can't be run in "continuous" mode like the obsidian sync. Basic memory keeps track of which projects are being synced and where.

# Process


What we want is to have `systemctl` run the commands automatically whenever the file-relay server is on, which should be all the time. Since they have to be run in different ways, we have different units set up for each. Both are being run as _user_ units instead of system units, keeping the permissions local to the user.


## Obsidian: keeping several copies alive

For the Obsidian sync, we have a unit that looks like this:

```systemd title:obsidian-sync@.service
[Unit]
Description=Obsidian continuous sync for vault: %i
After=network-online.target
Wants=network-online.target
StartLimitIntervalSec=120
StartLimitBurst=5

[Service]
Type=simple
WorkingDirectory=%h/obsidian-sync/%i
ExecStart=/usr/bin/ob sync --continuous
Restart=always
RestartSec=10

[Install]
WantedBy=default.target
```

This file is saved as `~/.config/systemd/user/obsidian-sync@.service`

and this is started with the name of each vault that needs to be synced. These are [instantiated system units](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/using_systemd_unit_files_to_customize_and_optimize_your_system/assembly_working-with-systemd-unit-files_working-with-systemd#con_working-with-instantiated-units_assembly_working-with-systemd-unit-files), defined by `templatename@unitname.service`. 

Each of those service units should be configured to start automatically, and I am running them as _user_ units, not system units. To check the status of all the services you can run:

```bash
systemctl --user status 'obsidian-sync@*'
```

to get the status of all the services from this template. 


## Basic Memory: Dynamic Syncs

 Since Basic Memory doesn't provide a continuous sync option, we instead have to create a bash script. This script does two things: first it checks with basic memory to see which projects are set up for sync, then it runs the sync for all those projects.

```bash title:bm-sync-all
#!/usr/bin/env bash
set -euo pipefail

projects=$(bm project list --json | jq -r '.projects[] | select(.sync == true) | .name')

if [[ -z "$projects" ]]; then
    echo "No sync-enabled projects found."
    exit 0
fi

pids=()
failed=()

for project in $projects; do
    echo "Starting sync: $project"
    bm cloud bisync --name "$project" &
    pids+=("$!:$project")
done

for entry in "${pids[@]}"; do
    pid="${entry%%:*}"
    name="${entry##*:}"
    if wait "$pid"; then
        echo "Completed: $name"
    else
        echo "Failed: $name (exit $?)"
        failed+=("$name")
    fi
done

if [[ ${#failed[@]} -gt 0 ]]; then
    echo "Sync failed for: ${failed[*]}"
fi

```


This is run by a service with a timer, set to go off every five minutes, with `oneshot` set so that it doesn't overlap itself.
