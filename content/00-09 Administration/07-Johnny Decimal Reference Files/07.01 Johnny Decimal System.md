# Introduction

First off, the homepage is laid out using this system: 

[Johnnydecimal.com](https://johnnydecimal.com/)

There are a few levels of complexity around this whole thing... First is keeping a centralized record of what categories are being used where. This is the [[00-JDex|JDex]], a central concept in the whole system. The JDex is the "card catalog". 

Then you create the _actual_ system outside of that. The core tenet is that you give everything a _sensible_ and _searchable_ address in your system. These addresses are called `AC.ID` addresses. 

## AC.ID

* The **A** is an _area_. This is the first digit in the overall address of an item. 
* The **C** is a _category_. This is the second digit.
* the **ID** is the two-digit unique ID of a specific item.
### Areas
The system supports ten **areas**, numbered 0 - 9. These are represented in Obsidian as folders with names like `00-09 Administration`. This tells us that any AC.ID address that starts with a zero is part of Administration. too see the current list of all current areas and categories, look [[00-JDex|here]].

### Categories
Each Area can have ten **Categories**. These are related containers within the Area. In Obsidian these are folders as well, named things like `21 - Ruby` which is inside `20-29 Programming Languages`. 

### IDs
Each Category can have one hundred IDs, from `00` to `99`. These are (ideally) self-contained _items_, the "atomic" level of organization.

| Term     | Meaning                                        | Example                       |
| -------- | ---------------------------------------------- | ----------------------------- |
| Area     | A collection of ten related groups             | `20-29 Programming Languages` |
| Category | A collection of up to one hundred items        | `21 Ruby`                     |
| Item     | A single, atomic record, with an AC.ID address | 21.01 Ruby Language           |

## JDex

When you want to make changes to the organization,  you make them in the JDex. When you want to find where something goes, you look in the JDex. The purpose of the JDex is to be the master record, the prime index of all facets of the system.

### How I Use It
The creator of this system keeps the JDex in a separate note-taking system, because he assigns AC.ID addresses to many items in many systems, like emails and stored files on other hard drives or whatever. 

I don't do that. 

I'm only using the JDex to organize a knowledge base. Like this one. So for ease of use (at the cost of only a few headaches), the JDex lives within the system it is indexing. Specifically, the JDex lives in [[00-JDex]], which is inside [[00-09 Administration/00-JDex/00-09 Administration/00-09 Administration|00-09 Administration]]. 

The JDex is the master list of **Areas** and **Categories**. In my system it is a bunch of empty directories with Folder Notes. the [[00-JDex]] Folder note _transcludes_ all of the Area folder notes. And each System directory simply transcludes the folder note of the relevant JDex folder. 

![[JDex Screencap.png]]


> [!QUESTION] Why Empty Folders?
> Good question! In short, it's because I expect this system to get weird. I'm sure that I will end up having Categories that spawn Subcategories. Or need extra explanation. So each Area is a folder. At some point they might have Category folders inside them. We will see. This will either end up being "future proofing" or "early optimization". 


## System

So the JDex is a lot of empty directories that tell you what should go into the actual _working_ directories of the system. 

The system is where that happens. Actual _notes_ and _files_ and _etc_ get stored in the System. Which looks kinda like this:

![[Pasted image 20260116134542.png]]

In this screen shot we see:
- The *Area*, which is Programming Languages. Any AC.ID address that starts with a `2` will be about a programming language. 
    - The *Category*, which is Ruby. It starts with a 2, and the second digit is a 1, meaning it's the first Category in the Programming Languages Area.
        - the **ID** which is `01`, the first note in the Ruby Category, a #TopicPage note about the Ruby Language. 

So the full AC.ID address of the note "Ruby Language" is 21.01. If I created a second note about various versions of ruby, that could be `21.02 - Ruby Versions`.
